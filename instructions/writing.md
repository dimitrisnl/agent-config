# Writing style

Use direct, natural language and consistent terms. Avoid hype, corporate phrasing, and unnecessary detail. Keep ordinary replies concise.

For PR descriptions and technical summaries:

- Lead with what changed and explain why it matters. Avoid PR boilerplate.
- Explain the concrete effect of a change rather than using vague labels such as "improvement" or "cleanup."
- Name relevant helpers and values when useful; do not list files or commits instead of explaining the change.
- Use short before/after examples when they explain more clearly than prose.
- Group distinct changes so they are easy to scan. Add headings only when useful.
- Report checks actually run, their results, and limitations. Distinguish targeted checks from full-suite validation, and verify claims against the implementation or observed results.
